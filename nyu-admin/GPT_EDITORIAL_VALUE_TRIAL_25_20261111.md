# ぜんにゅー GPT編集価値検証 25件 Ver.0.1

実施：2026-11-11。**OpenAI API契約・有料呼出しなし**。既存の`noapi_20261111_v01` 25件を、ChatGPTの文章編集機能で別案として書き直した。

## 実施内容
- 25件のファクトパックおよび元ニュースタイトル、実施段階、数値、根拠の留保事項を取得。
- GPTで独立した見出し・短い本文・暫定掲載判断・判断理由を作成し、`nyu_template_draft_trials` の `gpt_draft_title` / `gpt_draft_body` / `gpt_editorial_decision` / `gpt_editorial_reason` / `gpt_reviewed_at` に保存。
- 編集デスクの既存の試験画面`nyu-admin/template-draft-trials.html`を、GPT編集文・AIなし定型文・元ニュース・既存記事を比較できるものに拡張。
- `nyu_articles` / `nyu_evaluations` には一切保存しない。自動公開も行わない。
- 既存ニュースの要約で公式HTMLの厳格な自動照合が取れていたのは25件中**1件のみ**。その他24件は「再確認が必要」のままで、GPTが流暢に書き直しても事実検証済みにはならない。
- 過去記事との比較用13件は既存記事を変更せずスナップショットを表示。

## GPT版で確認できた編集上の利点

- 事実を読む順番を「何が起こった→何が変わる→何が未確認」に再配置できる。
- 制度・技術のニュースでは、読者が過大に捉えがちな内容を抑制する文章が書ける。
- 一般のゲーム発売・イベント告知と、「文化を保存する」活動を区別した仮編集判断を試みられる。
- 旧ファクトパックから算出した数字・出来事の段階を落とさず読みやすく書く方向性が確認できた。

## 実例

1. 「公営住宅のひとり親控除」：原稿版は政令改正・控除額のメモ風、GPT版は政府の閣議決定→対象制度→即時家賃引下げではないことを整理。旧記事も同じ論点が伝わり、GPTが既存記事を必ず超えているわけではない。
2. 「Phantom Blade Zero」：売上好調というニュース自体は成立するが、生活や社会改善の善兆に直結しないとしてGPTは暫定見送り。
3. 「料理マスターズ」：既成の「受賞者7人決定」と未来の「授与式予定」を区別。公式本文への厳格な照合が取れている唯一のサンプル。
4. 「ガバメントAI 源内」：アンケート回答者と時間短縮を実感した比率を紹介し、自己申告という性格を明記。
5. 「GOG」：単なるゲーム販売ではなく、互換性維持と文化保存の価値を説明。

## 重要な限界

- 編集の品質評価はGPT自身の作成内容と文字数などの機械的比較にとどまる。**第三者・ユーザーによるブラインドの品質評価、GPTなし定型文を同条件で改善した場合の対照実験は未実施**。
- GPT編集では「意味が通りやすい説明」に見える文章が元資料にない可能性がある。正式掲載には根拠原文との突合が必要。
- 出典元のファクトパックそのものが不完全な場合、GPTは誤りを滑らかな文章に変えてしまう危険性がある。
- GPTをChatGPTのセッションで手作業編集したのであって、OpenAI APIを実際に呼んだわけではない。実APIの価格、構造化出力、安定性・実行時間・再現性は検証していない。
- 掲載基準の14/7/4分類は編集者の暫定判断に過ぎない。正式スコア・自動公開閾値に流用しない。
- GitHub管理画面の実ブラウザー操作は未確認。RLSは既存の管理者だけが閲覧可能であることを以前のDB試験で確認済み。

## 技術安全性

- `nyu_template_draft_trials` は試験専用。RLSあり、公開不可制約あり、公開RPCから分離。
- 25件すべてGPT欄の保存成功。
- 最終DB：公開29、非公開13、評価130、ファクトパック74。試験データから公開可能な行は0。
- 模擬パイプライン・有料API・自動公開の設定は変更していない。

## 判定

**GPTの編集能力は、定型文だけでは難しい見出し作成・情報の順序付け・不確実性の説明・掲載価値の分類に適していることを25件のデモで確認**。
ただし**「APIに費用をかける価値が確実にある」「自動掲載品質になった」とはまだ結論できない**。次は20〜25件を人間が匿名化A/Bで採点し、好みだけでなく「追加・誇張・省略の誤り」と「善兆基準との整合性」を分けて採点する。
