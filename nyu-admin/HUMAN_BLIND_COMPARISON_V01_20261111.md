# 『ぜんにゅー』人間によるブラインド比較 Ver.1.0

実装日：2026年11月11日

## 目的
25件の「AIなし定型文」「GPT編集」「既存記事（ある場合）」を、回答前に作成方式を伏せて人間が採点し、API契約の費用対効果を判断する材料にする。

## 試験の構成
- 対象：`nyu_template_draft_trials` の `trial_batch=noapi_20261111_v01`
- 質問数 **25**。12問は2択、13問は3択。合計 **63案**。
- 各問の案A/B/Cの順序は固定seedのハッシュで変更。問題の順番も固定seedで表示。
- 第1段階：作成者・出典・原文を伏せたタイトルと本文だけを見て、各案の **読みやすさ・理解のしやすさ・善兆として読む価値** を1〜5点で採点し、最優秀案を1つ選択。
- 第2段階：第1段階を確定した後に元ニュースのタイトル・出典URL・厳格な照合の有無を表示。各案の **事実への忠実さ（1〜5、判断不能0）**、要修正の有無、任意の理由（500字まで）を記録。
- 第2段階の全案評価を確定後に作成方式（GPT、定型文、既存記事）を公開。**同じ文章の案も文字列推測ではなく、DB側の正確な変種IDで識別**。
- 全25問の第1・2段階を完了後、編集方式別の採用率・平均評価・要修正数を自動集計。A/Bの2択とA/B/Cの3択の表示回数を分母にした採用率を算出。
- 保存済みの回答から再開可能。回答確定後の上書きは原則禁止。

## セキュリティ
- `nyu_blind_review_options` は `security_invoker=true` のビュー。ソースの識別フィールドを持たない。
- `nyu_blind_style_ratings` と `nyu_blind_fact_ratings` にRLSを有効化。ログインした有効な管理者が、自分の回答だけ保存・閲覧可能。未ログイン者は不可。
- 事実確認の回答は、第1段階の同一案への回答が保存されていなければINSERTできない。
- `nyu_blind_review_reveal` は `security_invoker=true` のビュー。対象問題の第1、第2段階で全案の回答が保存された場合だけ対応表を返す。
- テストのINSERTは全て `BEGIN/ROLLBACK`。第2段階の先行書き込み拒否、早期種明かし防止、回答後の種明かし63案中の2案で正確に動くことを検証。
- この画面には記事公開、編集デスクの正式採点、API呼び出しの操作は存在しない。
- 自動公開不可フラグ `publication_eligibility=false` は25件全て維持。
- GitHub画面: `nyu-admin/blind-review.html`、編集デスク `nyu-admin/index.html` に入口追加。

## 方法上の制約
- 既に編集デスクの「GPT編集 vs 定型文」比較画面でラベル付き記事を閲覧できるため、評価者が以前見た原稿を覚えている可能性がある。**厳密な二重盲検にはならない**。
- 文体・長さからGPTを推測する可能性がある。
- たった1名の編集者の採点では統計的な一般化はできない。API契約の編集判断材料に使う。
- 文章の自然さと事実の正確性は別に評価する。未照合の24件は、GPT編集でも「検証済み」にはならない。
- GPTの自己評価を人間の回答として登録していない。

## 使い方
1. https://blacksmith-tombokiri.github.io/nyu-network/nyu-admin/?brand=zen に管理者ログイン。
2. 「人間による記事ブラインド比較」→「ブラインド比較を開始」。
3. A/B/Cを3項目で1〜5点評価し、最も良い案を選択して確定。
4. 元資料で事実への忠実さを確認し、各案を採点。確認できない場合は「判断できない」。
5. 回答後の種明かしを確認。25件終了後に自動集計を表示。
6. 既存のラベル付き記事比較を先に読み直すと盲検性が落ちるため、可能ならブラインド画面を先に使う。
