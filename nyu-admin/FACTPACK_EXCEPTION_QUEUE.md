# ぜんにゅー：ファクトパック例外確認キュー v0.1

## 動作方針
全記事を人手承認に回さず、Greenかつ利用許可済み、事前判定が `ai_candidate` の記事について自動的な出典照合を試みる。自動で確認できた場合は別経路で `complete` になり、模擬評価へ進める。自動照合できない場合は記事の主題をルールベースで確認し、**編集上の検討余地がある記事のみ** `review` に登録、明らかなルーチン記事・関連性が薄い記事は `skip` として記録する。

これはAIによる掲載価値の判定ではない。保留・除外は暫定ルールによるもの。元情報の真偽の保証でもない。

## 実装内容
- DB: `public.nyu_factpack_review_queue`（source_item_idごとに一意、decision=review/skip、status=pending/dismissed/resolved、reason_codes、記録日時）
- 管理者専用の参照RLS。他者が確認待ち情報を閲覧できない
- `public.nyu_set_factpack_review_queue_status`: 管理者が「確認対象から除外」にする操作、理由必須
- `public.nyu_prepare_factpack_from_queue`: 管理者が元記事の根拠を入力して、承認前の `needs_review` ファクトパックを作成。作成後はキューを `resolved` にする。承認処理は既存 `nyu_review_factpack` で別途実施
- 管理画面 `nyu-admin/factpack-queue.html`。編集デスクからリンク
- `nyu-factpack-auto` Edge Function v7の `route_queue` モードで10件ずつ判定。既存レコード・先行処理済み記事は除外し、重複登録しない
- Supabase Cron `nyu-factpack-exception-routing`、毎時35分（cronはUTC表記、毎時なので日本時間でも毎時35分）に実行。秘密トークンはVaultから実行時取得。**既存のRSS取得・AI採点・記事公開をCronに追加していない**

## 判定ルール
1. 自動確認済み： `auto_source_verified_v1` の従来方式で正常に完了。キューへは登録しない
2. 要確認：公式本文が取得できない／証拠不十分／表現不一致などで自動確認失敗、かつ見出しに福祉・医療・支援・教育・自然・環境・技術開発・研究・表彰等の編集上の可能性がある
3. 除外：一般的なゲーム配信更新、イベント・キャンペーンの案内、単純な定期更新など、現時点で価値シグナルのない記事
4. 既存ファクトパック／評価／掲載記事は上書きや再登録をしない

**注意**：判定語句は初期版であり、誤除外・過剰送付の可能性がある。特に「除外」は公開しないだけで記録は残すが、管理画面には除外一覧をまだ実装していない。運用データを見ながら改善すること。

## テスト
- 初回実行時、保存のJSONB型問題が発生。ログを確認して `db.json` を使用し修正した
- `route_queue` 成功（HTTP 200）、初回10件に対し要確認1・除外6・既存維持3
- 複数回実行し、処理済みアイテムを再登録しないことを確認
- 初期検証で確認待ち5件・除外22件、ファクトパック73件（うち既存 `needs_review` 1件）、公開記事29件、評価記録130件
