# ぜんにゅー｜事実先行採点 → 編集分離 Ver.0.5 実装記録（70点ゲート修正版）

実施日: 2026-11-11

## 目的

**① 元情報・検証済みファクトパック → ② 事実だけで100点評価、点数を保存し固定 → ③ 70点以上の案件に限りVer.0.2.1の記事本文・善兆コメント・評価理由を編集。**

「善兆らしく説明する力」がスコアへ混入しないよう、入出力と処理順を物理的に分離した。

## 実装対象

### データベース

- `public.nyu_v05_fact_scores`：採点専用。ファクトパックID、検証済みの原文・数値・実施段階を含む`source_snapshot`、指紋SHA-256、共通60点、カテゴリ40点、合計（DB生成列）、採点根拠、採点者、バージョンを保存。
- `public.nyu_v05_editorial_drafts`：記事編集専用。固定スコアIDを参照して見出し・本文・善兆コメント・評価理由を保存。公開不可フラグにはCHECK制約。
- RLS＋ロール権限：管理者以外は読み取り0件。一般ユーザーの直接書き込み権限なし。採点・記事下書きの作成は管理者認証付きRPCを介す。
- `nyu_private.nyu_v05_source_snapshot(factpack_id)`：一次情報から厳格に検証した構造化ファクトだけを元DBから抽出。自動検証が`auto_source_verified_v1`、`ready_for_scoring=true`、URL整合、根拠抜粋、ハッシュ、著作権許諾条件などを要求。未検証・既存評価または既存記事がある案件は拒否。
- `public.nyu_v05_scoring_candidates(limit)`：事実・根拠・指紋だけを返す。記事本文・善兆コメント・評価理由の入力経路なし。
- `public.nyu_v05_record_fact_score(...)`：事実スナップショットを再取得し、表示時と保存時の指紋一致を要求。スコアは60+40、点数と根拠を作成時に確定。管理者でも表への直接UPDATEは不可。
- `public.nyu_v05_save_editorial_draft(...)`：スコア70点以上、同じ根拠指紋、下書き未作成、管理者認証、すべて成立する場合のみ記事案を試験用テーブルに保存。

### 管理画面

- [採点→編集 Ver.0.5](https://blacksmith-tombokiri.github.io/nyu-network/nyu-admin/facts-first-editorial-v05.html)
- 編集デスク `nyu-admin/index.html` からアクセスできる。
- 初期状態は根拠確認。採点完了するまで下書き編集フォームが開かない。
- 保存済みスコアのうち70点以上のみ本文編集が可能。既存スコアは変更しない。
- 管理者用画面であり、公開ニュース記事ページとは独立。

## 現状の適用範囲（必ず区別）

- **実際に動作するのは安全な手動採点・手動編集の試験ワークフロー。**
- OpenAI有料APIは未使用。AIによる本物の自動評価や自動記事生成は未実装。
- 従来の `nyu-pipeline` → `nyu-ai-safety-runner` → `nyu-evaluator-mock` は引き続き模擬試験専用であり、このVer.0.5のテーブルに接続していない。従来の模擬エンジンにはスコアと文章案を同時に返す古い出力形式が残る。
- 一般公開記事の評価テーブル`nyu_evaluations`、記事テーブル`nyu_articles`、その他の公開設定は変更なし。
- 今回の試験用確定スコアを正式な善兆スコアと同一視しない。
- 登録済みの高い信頼度を持つ厳格な自動確認ファクトパックが現時点で**1件**。今後この入口を通れる案件を増やすにはファクトパック検証性能向上が別途必要。
- 正式なAI採点・自動文章編集へ接続する前に、(1) 採点プロンプトのJSON出力を点数・根拠のみへ変更 (2) 文案生成プロンプトを別処理にする (3) 品質チェックと任意の公開承認を追加 (4) 従来の模擬評価から段階的に切替、が必要。

## テスト結果

**トランザクション内で行い、最後にすべてROLLBACK。**

1. 不正な出典指紋による点数登録 → `source_changed_recheck_required` で拒否。
2. 事実に基づき65点を登録 → 下書き作成 `below_editorial_threshold` で拒否。
3. 事実に基づき84点を登録 → 下書き作成を許可、公開フラグはfalse。
4. 84点の文章を保存した後の点数 → **84点を維持**。
5. 管理者ロールの直接UPDATE → 権限不足で拒否。
6. 未認証・非管理者のRPC操作 → `admin_required` で拒否。
7. いずれも本番の記事テーブルには変更しない。
8. 試験後：新テーブルにスコア0件、下書き0件。既存公開29件、非公開13件。

## セキュリティ監査

Supabase Security Advisor を実行した。新規のRPCはSECURITY DEFINERの一般警告対象になるが、関数の先頭で`nyu_private.nyu_v05_assert_admin()`が認証ユーザーと登録済み編集権限を明示確認。未認証/非管理者の実操作を検査済み。既存の`pg_net`公開スキーマ・漏洩パスワード保護設定などの既存警告は今回の変更範囲外。

## 次の段階

まずこの画面で、検証済みファクトパックを事実だけで手動採点し、70点以上ならVer.0.2.1の編集稿を試す。データが十分蓄積した後、**採点のみのAI**と**記事生成のみのAI**を独立した処理として実装し、別途承認してから旧模擬パイプラインの接続先を切り替える。現状、APIや自動公開を無断で有効化しない。

## 70点ゲートへの正式修正・AI二段階処理（追記）

**2026-11-11：ユーザー指定で採点→編集の基準を「70点以上」に訂正。前掲の旧80点仕様よりこの節を優先する。**

- **0〜69点**：採点記録のみ。記事生成AI呼び出し不可。
- **70〜79点**：採点を固定後、記事生成AIへ渡す。**人間の掲載可否判断が必須**。掲載は自動化しない。
- **80〜100点**：採点を固定後、記事生成AIへ渡す。通常の掲載候補だが、出典・品質・権利・運用承認は別途必要。

### 稼働する実装

- 保存用RPC `public.nyu_v05_record_fact_score`：編集アンロック70点へ修正。
- 保存用RPC `public.nyu_v05_save_editorial_draft`：70点以上を許可、元資料の指紋照合と二重作成拒否を維持。
- 管理画面 `nyu-admin/facts-first-editorial-v05.html`：70〜79点を編集可能かつ人間掲載判断必須として表示。
- `public.nyu_v05_get_scoring_input`：管理者限定で採点専用のファクトパック入力を返す。生成済み文章は渡さない。
- `nyu_private.nyu_v05_record_ai_score`：AI専用の点数、共通4項目内訳、カテゴリ40点、採点根拠、利用モデル・提供者リクエストIDを保存。AIスコアは編集と独立。
- Edge Function **`nyu-v05-ai-score`**：ファクトパックだけを受けてスコア・内訳・根拠だけを生成、保存してから70点以上の場合に限り別のAI記事生成関数へ処理を引き渡す。
- Edge Function **`nyu-v05-ai-editorial`**：固定済みのスコアと事実だけを入力とし、Ver.0.2.1の見出し・本文・善兆コメント・「なぜ善兆なのか」を生成。スコアを変更しない。70点未満なら拒否。
- いずれも管理者認証に加え、課金AI実行時には `NYU_V05_AI_ENABLED=true`、OpenAI APIキー、モデル、`nyu_private.nyu_ai_safety_policies(scope='live')` の enabled/api_enabled=true・回路停止なし、実行予約の成功をすべて要求する。**現状は未有効化のため、有料AI呼び出しは0件。**
- 両関数は`preview`/ `contract_test` モードを持ち、API課金なしで入力契約・境界ケースを調べられる。
- `nyu-evaluator-mock` など従来の模擬評価処理とは独立。従来の自動スケジュールを今回のAPIへ勝手に変更しない。

### 実装テスト

- 管理者JWT権限のあるSQLトランザクションで**69点・70点・79点・80点**を一件ずつ保存し、記事生成可否・人間判断ルート・点数不変を確認。**各テストはROLLBACK**。
- AIスコア用内部関数で、共通4項目47点＋カテゴリ23点の**70点**が `human_review_required` となり、本文下書きが保存前に存在しないことを確認。ROLLBACK。
- 有料AIの実リクエストは行っていない。外部プロバイダとのエンドツーエンド呼び出しは未検証。
- AI生成後の事実確認・公開承認システムは別工程。今回の生成下書きはサイト記事テーブルに書き込まれず公開不可。

**重要：この改修は、AI接続と70点ルーティングの実装であり、有料APIの運転開始を意味しない。**
