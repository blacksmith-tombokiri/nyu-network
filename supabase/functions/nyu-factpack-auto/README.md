# NYUNET ファクトパック自動確認ルート v0.1

## 目的と基本方針

**すべての記事を人が承認するのではない。** 自動で確認可能な根拠が揃った記事は模擬AI評価の候補として通し、足りない記事だけ人間が調べる。これは出典に記載された内容を確認する仕組みで、記事に含まれる主張の独立した真偽や善兆スコアを自動認証するものではない。

## 自動確認の最小条件（すべて必須）

1. Green／商用利用可／本番利用可／再利用承認済みで、停止・削除要求なしの出典
2. `source_type=government` または `public`
3. 事前フィルタ `ai_candidate`
4. 同じ記事のファクトパック・評価・公開記事が既存にない
5. 取得URLが承認済みドメイン内のHTTPSで、元記事のHTML `main` または `article` から本文が取得できる（PDF、RSS要約のみは不可）
6. 元記事タイトルが本文に**完全一致**し、元記事の公開日が本文中の認識可能な表記に一致
7. タイトルが明確な発表・公表・掲載・公開・決定等の行為を表し、予定・実証・効果・成果・危険性の高い語を含まない
8. テキスト長・出典抜粋長が十分で、文字化けがない
9. 抽出した行為のみを `event_summary` と `change_summary` に記録し、実際の施策の効果・成果を断定しない
10. SHA-256形式の出典抜粋ハッシュ、取得日時、出典URL、検証方法、留保事項を保存

上記を満たす場合だけ `extraction_status=complete`、`review_type=auto_source_verified_v1`、`ready_for_scoring=true` を保存できる。**`ready_for_publication=false` を維持する。**

その他は `needs_review` と判定するか既存レコードを保護する。現版は**自動判定が失敗した記事をすべて管理画面に保存するわけではない**。未登録記事のレビュー待ちキューへの自動登録は次段階の課題。

## 実装

- Supabase Edge Function: `nyu-factpack-auto`
- ソース: `supabase/functions/nyu-factpack-auto/index.ts`
- `mode=fixtures`: 架空データによる4ケース試験
- `mode=preview`: 実記事から公式HTMLを取得して読み取りのみの判定（最大5件）
- `mode=auto_save`: 安全条件をすべて満たした**新規**ファクトパックだけ `complete` として保存。既存は `ON CONFLICT DO NOTHING` で維持
- `nyu-evaluator-mock` v4: `human_verified_source` と `auto_source_verified_v1` の2経路に対応。自動ルートではソース区分、照合した元URL、取得日時、厳格な本文抜粋、必要項目を検査。旧形式completeを通さない
- 自動評価や掲載操作を有効にしたわけではない。Cronによる自動巡回・自動確認は未接続

## テスト（2026-11-10）

| ケース | 結果 |
|---|---|
| 架空の根拠十分な公式HTML | PASS |
| 将来計画や成果を含む曖昧な見出し | BLOCK |
| RSS要約だけ | BLOCK |
| 既存ファクトパックあり | BLOCK |
| 人間が承認した架空データ | PASS |
| 自動確認済みの架空データ | PASS |
| 旧complete、未承認、出典URL相違、評価済み | BLOCK |
| PDFの実記事で `auto_save` | 自動確認を拒否、DB書き込み0 |
| 既存completeの実記事で `auto_save` | 既存を維持、DB書き込み0 |
| 実際の候補3件のプレビュー | 自動通過0件、DB書き込み0 |
| 有料API・記事公開 | 呼び出し0・公開0 |

実記事の自動確認済みファクトパックは現時点0件である。**実記事が実際に自動通過して模擬AI評価へ進む本番相当の結合テストは未完了。**

## 制約と次の改善

- タイトルと日付の完全一致を要求する現版はかなり保守的。ページの表記揺れにより自動通過しない場合がある
- PDF本文の解析、ページ固有HTMLの精密抽出は未実装
- `needs_review` の返却と、人が見る管理画面のレビュー待ちキューへの追加はまだ別工程
- 単純なHTML抽出は主張の真偽や、日付と見出しの意味的関連を保証しない
- 自動通過が可能な案件を増やすときは、基準を緩めるより情報源ごとに公式本文の信頼できる抽出方式を改善する
- 有料API接続前に、出典抜粋の再ハッシュ、出典改変時の失効、最新本文の再確認、監査ログ、費用制限の整合性を追加検証

**正式な善兆スコア評価、記事の自動公開は現在も無効。**
